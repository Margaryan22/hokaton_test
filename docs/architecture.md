# Архитектура

Бриф: `.crew/brief.md`. Стек: ADR-001, `.crew/stack/README.md`. Решения: ADR-002 (слои), ADR-003 (диалог), ADR-004 (даты), ADR-005 (поиск), ADR-006 (импорт CSV), ADR-007 (без LLM).
Пример «сейчас» везде — понедельник 2026-10-19 10:00 МСК (`APP_NOW`).

## 1. Слои

```
Браузер                         Сервер (Node, Next route handlers)
┌──────────────────────┐        ┌──────────────────────────────────────────────────────────┐
│ голос  src/client/speech│ text │ HTTP  src/app/api/**  (Zod, uid из cookie, now())          │
│ UI     src/components  │─────▶│   │                                                       │
│ api    src/client/api.ts│◀────│   ▼                                                       │
└──────────────────────┘ JSON   │ Диалог  src/server/dialog  (автомат, транзакция, ответы)   │
                                │   ├──▶ NLU     src/server/nlu     parse(text, expect, now) │
                                │   ├──▶ Поиск   src/server/search  searchRecords / targets  │
                                │   └──▶ Сервисы src/server/services (записи, конфликты)     │
                                │              └──▶ Хранение src/db (Drizzle, по userId)      │
                                └──────────────────────────────────────────────────────────┘
```

Четыре слоя из ТЗ: **голос** — `src/client/speech` (Web Speech API в браузере); **понимание запроса** — `src/server/nlu` (правила, даты) и `src/server/search` (ранжирование); **бизнес-логика** — `src/server/dialog` (автомат уточнений, подтверждения, контекст) и `src/server/services` (записи, конфликты встреч, лимит запросов); **хранение** — `src/db` (Drizzle + libSQL/Turso). HTTP-слой `src/app/api` только связывает их.

Правило импорта (ADR-002): api → dialog → {nlu, search, services, replies}; services → {db, search}; `nlu` и `search` чистые (только `src/shared`, luxon, snowball-stemmers, fastest-levenshtein); `src/db` не импортирует `src/server`; клиент импортирует только `src/shared` и `src/client` (закреплено ESLint `no-restricted-imports` в `eslint.config.mjs`).

## 2. Модель данных

`src/db/schema.ts`, таблицы snake_case, время — UTC мс (`timestamp_ms`).

**users**
| Поле | Тип | Ограничения |
|---|---|---|
| id | integer PK autoincrement | |
| name | text | 1–40 символов после trim, как ввёл пользователь |
| name_key | text | unique; `normalize(name)` (нижний регистр, ё→е, пробелы схлопнуты) — «анна» и «Анна» один пользователь |
| created_at | timestamp_ms | default now |

**records** (запись: задача / встреча / напоминание)
| Поле | Тип | Ограничения |
|---|---|---|
| id | integer PK autoincrement | |
| user_id | integer FK users.id | not null, on delete cascade |
| kind | text enum `task` \| `meeting` \| `reminder` | not null |
| title | text | not null, 1–200, исходный регистр |
| due_date | text `YYYY-MM-DD` | null; день по Москве (ADR-004) |
| starts_at | timestamp_ms | null; CHECK `starts_at IS NULL OR due_date IS NOT NULL` |
| done | integer boolean | not null default false («не выполнено») |
| source_id | integer | null; id строки CSV; unique `(user_id, source_id)` (ADR-006) |
| created_at, updated_at | timestamp_ms | not null |

Индексы: `records_user_due_idx (user_id, due_date)`, `records_user_source_unique (user_id, source_id)`.
Инварианты сервиса: meeting и reminder имеют `due_date` и `starts_at`; task — оба необязательны; `due_date` = московская дата `starts_at`. Удаление — физическое (запись исчезает из списков и поиска, AC-15). Длительность встречи для конфликтов — 1 час, в БД не хранится.

**dialog_messages** (история для экрана)
| Поле | Тип | Ограничения |
|---|---|---|
| id | integer PK | |
| user_id | integer FK | cascade; индекс `(user_id, id)` |
| role | text enum `user` \| `assistant` | |
| text | text | ≤ 500 для user |
| items_json | text null | снимок `RecordDto[]`, показанных в ответе |
| created_at | timestamp_ms | |

**dialog_states** (ADR-003) — `user_id` PK FK cascade; `state_json` text not null default `{"kind":"idle"}`; `focus_record_id` integer null FK records.id on delete set null; `updated_at`.

**Сид** (`npm run db:seed`, идемпотентный): пользователь «Демо» + 1000 записей CSV по ADR-006 (тип: начало текста «встреч»/«созвон»/«демо» или «планерк» внутри → meeting; начало «напомн» → reminder; иначе task; `done=false`). Других пользователей и записей сид не создаёт.

## 3. Роли и права

Одна роль «Пользователь»; пароля нет (бриф). Текущий пользователь = httpOnly cookie `uid`, поставленная `POST /api/session`.

| Действие | Пользователь (свои данные) | Чужие данные | Без cookie |
|---|---|---|---|
| Выбрать/создать пользователя по имени, видеть список имён | да | — | да |
| Создать / посмотреть / найти запись | да | нет (как «не найдено») | 401 `no_user` |
| Перенести, отметить выполненной | да | нет | 401 |
| Удалить | да, только после «да» на вопрос подтверждения | нет | 401 |
| История диалога, «Новый диалог» | да | нет | 401 |

Каждая функция репозитория принимает `userId` и кладёт его в `WHERE`, включая update/delete по id.

## 4. API (всё JSON; ошибки `{ error: { code, message } }`, сообщение по-русски)

Zod-схемы входа — `src/shared/schemas.ts` (zod.md), DTO-типы — `src/shared/api.ts`, форматирование дат — `src/shared/format.ts`.

```ts
type RecordKind = "task" | "meeting" | "reminder";
type RecordDto = { id: number; kind: RecordKind; title: string; date: string | null; time: string | null; done: boolean };
type MessageDto = { id: number; role: "user" | "assistant"; text: string; items: RecordDto[] | null; createdAt: string };
type Panel = { title: string; items: RecordDto[]; total: number };          // правая колонка «Записи»
type Awaiting = "slot" | "yes_no" | "choice" | "target" | null;
type ChatResponse = { messages: [MessageDto, MessageDto]; panel: Panel; awaiting: Awaiting };
```

| Метод и путь | Вход | Выход | Заметки |
|---|---|---|---|
| `GET /api/users` | — | `{ users: {id,name}[] }` | для переключателя |
| `GET /api/session` | — | `{ user: {id,name} \| null }` | |
| `POST /api/session` | `{ name }` (1–40) | `{ user }` + cookie `uid` | найти по `name_key` или создать — одно действие (AC-20) |
| `POST /api/chat` | `{ text }` (1–500) | `ChatResponse` | единственная точка для голоса и текста |
| `GET /api/dialog` | — | `{ messages: MessageDto[] (последние 50), awaiting, panel }` | загрузка страницы |
| `POST /api/dialog/reset` | — | `{ ok: true }` | «Новый диалог»: стирает реплики, состояние, фокус |
| `GET /api/records` | — | `Panel` | вид по умолчанию «Ближайшие» |
| `PATCH /api/records/[id]` | `{ done: boolean }` | `{ record }` | чекбокс в списке; 404 для чужой |
| `GET /api/health` | — | `{ ok, now }` | есть в скелете |

`panel` в ответе чата: для `list`/`search` — этот же результат (заголовок = период/запрос, AC-07: на экране и в ответе одни записи); для остальных интентов — «Ближайшие»: записи с `due_date >= сегодня` или без даты, порядок ADR-004, до 50. Текст ответа перечисляет до 10 записей и «…и ещё N».

## 5. NLU (`src/server/nlu`)

Файлы: `normalize.ts` (нижний регистр, ё→е, пунктуация → пробел, числительные словами → цифры: «два»→2, «полчаса», «час»→1), `dates.ts`, `intents.ts`, `title.ts`, `parse.ts`, `types.ts`. Токены хранят позиции в исходной строке, чтобы название бралось из оригинала с регистром («позвонить Ивану»).

**Интенты** (`Intent`, discriminated union):
| type | Слоты | Примеры |
|---|---|---|
| `create` | kind, title?, date?, time?, hasDeadline | AC-01..AC-06 |
| `list` | period?, kind?, exists (для «есть ли») | AC-06..AC-09, AC-22 |
| `search` | terms, kind?, tense? | AC-10..AC-12 |
| `update` | target, change {date?, time?} | «перенеси её на завтра» (AC-16) |
| `complete` | target | AC-15 |
| `delete` | target | AC-15, AC-17 |
| `confirm` | yes: boolean | «да», «конечно», «ставь» / «нет», «не надо» |
| `choose` | index 1..5 | «2», «вторую», «номер два» |
| `slot` | date?, time? (+ title?) | «в 14:30» (AC-05) |
| `cancel` | — | «отмена», «стоп», «не надо» в ожидании |
| `unknown` | — | «Как дела на Марсе?» (AC-13) |

`target` = `{ ref: "focus" }` (её/его/эту/этот/её) или `{ kind?, terms }` из оставшихся слов.

**Порядок правил** (первое совпадение выигрывает): 1) если `expect` задан — сначала форма ответа: `cancel`, `confirm` (yes_no), `choose` (choice), `slot` (slot: в реплике есть дата/время и нет ни глагола команды, ни маркера списка/поиска), для `target` — любая некомандная реплика становится terms; 2) `delete` (удали/удалить/убери/сотри); 3) `complete` (отметь … выполнен*/сделан*); 4) `update` (перенеси/перенести/передвинь/сдвинь/измени время); 5) `search` (найди/найти/поищи/«когда … был/была/было/будет»); 6) `list` (что у меня/какие/покажи/что запланировано/что было/есть ли/планы/расписание + период или тип); 7) `create`: начало «напомн» → reminder; иначе первое слово типа («задач» → task, «встреч»/«созвон»/«планерк»/«демо» → meeting); иначе task, если есть глагол создания (поставь/добавь/запиши/создай/запланируй/нужно/надо) или дата + слово встречи («В четверг в 11 у меня встреча…»); 8) `unknown`.

**Даты и время** (`dates.ts`, Luxon, зона Europe/Moscow, от переданного `now`):
- Дни: сегодня, завтра, послезавтра, «в <день недели>» = ближайший будущий (сегодня не считается), «D <месяц> [YYYY]» (год по умолчанию — ближайшая будущая дата, если год не указан), «через N дней».
- Срок: «до конца недели» = воскресенье текущей ISO-недели; «до <дня недели/даты>» = эта дата; `hasDeadline=true` для ответа «срок».
- Время: «в 14:30», «в 15», «в 10 утра», «в 3 дня», «в 7 вечера»; «утром» = 09:00, «днём» = 13:00, «вечером» = 19:00, «в полдень» = 12:00; «через N часов/минут», «через час», «через полчаса» → дата+время от `now`. Голый час 1–7 без «утра/ночи» → +12 (рабочий день), 8–23 как есть («в 11» = 11:00).
- Только время без даты: сегодня, если ещё не прошло, иначе завтра.
- Периоды для `list`: сегодня, завтра, послезавтра, эта неделя (пн–вс, AC-08: 19–25.10), следующая неделя (26.10–01.11), выходные, день недели, конкретная дата; без периода — «Ближайшие». Полуинтервал `[from, to)` дат.

**Название** (`title.ts`): из исходной фразы вырезаются глагол-команда, слово типа (для task/reminder), даты/время, служебные слова (мне, у меня, пожалуйста, нужно, надо, что). Для встречи — первое слово нормализуется в именительный: «встречу с командой» → «встреча с командой»; если остатка нет — «встреча». Для задачи/напоминания пустой остаток → `title` отсутствует → уточнение.

## 6. Диалоговый автомат (`src/server/dialog`, ADR-003)

`engine.ts` → `transition(state, intent, ctx)` → `{ nextState, effects, reply, panel, focus }`; всё в одной `db.transaction`.

| Состояние | expect | Вход → действие |
|---|---|---|
| `idle` | — | команда → выполнить (ниже) |
| `await_slot {draft, missing}` | slot | `slot` → дополнить draft; если всё есть → проверка конфликта → сохранить / `await_conflict`; если чего-то ещё нет → спросить следующее. Иная команда → сбросить и выполнить её. Непонятно → повторить вопрос |
| `await_conflict {write, conflictIds}` | yes_no | да → сохранить/применить; нет → «Хорошо, не ставлю.» → idle |
| `await_delete {recordId}` | yes_no | да → удалить, фокус = null, «Удалил задачу «…».»; нет → «Хорошо, не удаляю.» → idle |
| `await_choice {op, candidateIds, change?}` | choice | номер в диапазоне → op для выбранной: delete → `await_delete`; complete → выполнить; update → проверка конфликта → применить; вне диапазона → повтор |
| `await_target {op, change?}` | target | реплика → поиск цели как в idle |
| любое ожидание | | `cancel` → «Хорошо, отменил.» → idle; новая полноценная команда → idle + выполнить её |

**Команды в idle:**
- `create`: обязательные слоты — meeting: дата и время; reminder: дата и время; task: только название. Нет слота → вопрос и `await_slot`, ничего не сохраняется (AC-05). Вопросы: «На какое время поставить встречу?», «На какой день поставить встречу?», «Когда поставить встречу?» (нет обоих), «Во сколько напомнить?», «Когда напомнить?», «Что нужно сделать?». Для meeting — поиск конфликтов (интервал `[start, start+1ч)` против встреч пользователя, `a.start < b.end && b.start < a.end`); есть → `await_conflict` (AC-14). После сохранения фокус = новая запись.
- `list`: выборка по периоду и типу; `exists` → ответ начинается с «Да» / «Нет». Ровно одна запись → фокус.
- `search`: ADR-005; ровно одна → фокус.
- `update`/`complete`/`delete`: цель — `focus` или кандидаты ранжировщика (ADR-005; для complete — только невыполненные). Нет фокуса и нет terms → «Какую запись перенести?» / «…удалить?» / «…отметить выполненной?» + `await_target` (AC-16). 0 кандидатов → «Не нашёл …». Несколько → список до 5 + `await_choice` (AC-17). Одна: delete → вопрос + `await_delete` (AC-15); complete → done=true; update → новая дата/время (недостающая часть сохраняется: «на завтра» оставляет время), для встречи — проверка конфликтов (кроме неё самой).
- `confirm`/`choose`/`slot` в idle → «Сейчас нечего подтверждать. Что сделать?»; `unknown` → AC-13.

## 7. Ответы (`src/server/dialog/replies.ts`, тексты по-русски)

Даты — `src/shared/format.ts`: «20 октября», год добавляется, если не текущий («26 января 2024»); время «HH:mm».
| Ситуация | Шаблон |
|---|---|
| reminder создан | «Напомню 20 октября в 10:00: позвонить Ивану» |
| task создана | «Добавил задачу «отправить отчет» на 23 октября» / «… со сроком до 25 октября» / «… без срока» |
| meeting создана | «Поставил встречу «встреча с командой» на 20 октября в 15:00» |
| конфликт | «В это время уже есть встреча «встреча с командой» 20 октября в 15:00. Всё равно поставить?» |
| удаление? | «Удалить задачу «купить билеты»?» (встречу/напоминание — по типу) |
| выполнено | «Отметил задачу «купить билеты» выполненной» |
| перенос | «Перенёс встречу «встреча с дизайнером» на 20 октября в 11:00» |
| несколько | «Нашёл несколько задач: 1. подготовить отчёт для банка; 2. подготовить отчёт для клиента. Какую удалить?» (задач/встреч/напоминаний/записей; удалить/отметить выполненной/перенести) |
| список | «На сегодня: 1. 11:00 встреча с дизайнером; 2. отправить отчет» |
| пусто | «На <сегодня/завтра/эту неделю/следующую неделю/26 января 2024> ничего не запланировано» (AC-09) |
| есть ли | «Да, на сегодня 1 встреча: …» / «Нет, на сегодня встреч нет» |
| поиск | «Нашёл 3 встречи: 1. Встреча с Иваном по CRM — 4 апреля 2025, 18:00; …» |
| поиск пуст | «Ничего не нашёл. Попробуйте уточнить запрос: другое слово или период» (AC-12) |
| не понял | «Не понял запрос. Например: «Напомни завтра в 10 позвонить Ивану», «Что у меня на этой неделе?», «Найди задачу про отчёт»» (AC-13) |

## 8. Поиск (`src/server/search`, ADR-005)

`stem.ts` (snowball russian после normalize), `stopwords.ts`, `synonyms.ts` (группы основ: отчет/доклад; договор/контракт; созвон/звонок/встреч; презентац/слайд; бюджет/смет), `rank.ts` (`searchRecords`, `resolveTargets`). Фильтры kind и tense → балл (основа 1.0, префикс 0.8, синоним 0.6, нечёткое 0.4) → балл ↓, дата ↑, id ↑ → 5. Префиксное правило нужно: Snowball «иван»→«ива», «иваном»→«иван».

## 9. Клиент (`src/components`, `src/client`)

Одна страница: переключатель пользователя (список + поле «Новое имя»), лента диалога (`aria-live`), поле «Сообщение» + «Отправить», кнопка микрофона, «Звук: вкл/выкл» (localStorage `va:sound`, по умолчанию вкл), кнопка «Новый диалог», колонка «Записи» (`panel`, тип, текст, дата-время, статус, чекбокс). После каждого ответа чата — показать `panel` из ответа; озвучить `assistant.text`, если звук вкл. Нет распознавания или запрет микрофона → кнопка неактивна и «Голосовой ввод недоступен, введите текст».

## 10. Ошибки и валидация

- Zod на каждый вход; 400 `invalid_input` «Некорректные данные»; 401 `no_user` «Выберите пользователя»; 404 `not_found` «Запись не найдена»; 500 — без деталей.
- Ответ ассистента «не понял/уточните» — не ошибка, а 200 с репликой.
- Записи создаёт только сервис после полной валидации слотов; парсер никогда не пишет.

## 12. Допущения дизайна (бриф их не задаёт)

- Напоминание без времени требует уточнения «Во сколько напомнить?» (как встреча).
- Перенос встречи тоже проверяет конфликты.
- Голый час 1–7 трактуется как дневной (15:00 для «в 3»).
- «Ближайшие» в колонке записей включают выполненные (со статусом) и записи без даты.
