Задача
Разработать прототип голосового ассистента, который помогает пользователю управлять
личными задачами, напоминаниями и встречами с помощью естественной речи.

Пользователь должен иметь возможность обратиться к ассистенту голосом и текстом,
сформулировать запрос в свободной форме и получить голосовой или текстовый ответ.

Основной акцент тестового задания — не на интерфейсе, а на логике работы ассистента:
понимании пользовательского запроса, работе с данными и корректном выполнении
действий.

Основные сценарии
Ассистент должен поддерживать как минимум следующие сценарии:

 1. Создание задачи или напоминания

Пользователь может сказать или написать:

«Напомни мне завтра в 10 утра позвонить Ивану».

«В пятницу нужно отправить отчет».

«Поставь задачу купить билеты до конца недели».

Ассистент должен определить содержание задачи, дату и время, если они указаны,
сохранить информацию и подтвердить действие пользователю.

 2. Создание встречи

Например:

«Добавь встречу с командой завтра в 15:00».

«В четверг в 11 у меня встреча с дизайнером».

Ассистент должен определить название или содержание встречи, дату и время и
сохранить ее.

 3. Получение информации о предстоящих событиях

Пользователь может спросить:

«Что у меня сегодня?»
«Есть ли у меня встречи сегодня?»

«Какие задачи у меня на завтра?»

«Что запланировано на эту неделю?»

Ассистент должен найти соответствующие события и сформировать понятный ответ.

 4. Поиск старых задач и событий

Ассистент должен уметь находить ранее созданные записи по естественному запросу.

Например:

«Найди задачу про презентацию».

«Когда у меня была встреча с Иваном?»

«Я когда-то ставил задачу по договору, найди ее».

Не требуется точного совпадения формулировок. Желательно реализовать поиск,
который способен работать с близкими по смыслу запросами.

Работа с естественным языком
Пользователь не должен быть обязан использовать заранее определенные команды.

Например, следующие запросы должны интерпретироваться как один тип действия:

«Что у меня сегодня?»

«Какие планы на сегодня?»

«Покажи мои встречи на сегодня».

Также желательно учитывать относительные даты и время:

«сегодня»;
«завтра»;
«послезавтра»;
«в пятницу»;
«через два часа»;
«на следующей неделе».

Если информации недостаточно для выполнения действия, ассистент может задать
уточняющий вопрос.

Например:
Пользователь: «Поставь встречу с Иваном завтра».

Ассистент: «На какое время поставить встречу?»

Хранение данных
Необходимо реализовать хранение созданных пользователем задач и встреч.

Для каждой записи желательно хранить как минимум:

   тип записи: задача / встреча / напоминание;
   название или текст;
   дату и время;
   дату создания;
   статус выполнения — при необходимости.

Способ хранения данных кандидат выбирает самостоятельно.

Голосовой интерфейс
Минимальный пользовательский сценарий:

голос пользователя → распознавание речи → обработка запроса → выполнение
действия → ответ ассистента.

Допускается использование готовых API и библиотек для Speech-to-Text, Text-to-Speech и
LLM.

Интерфейс может быть минимальным. Например, достаточно страницы с кнопкой начала
записи, историей диалога и ответом ассистента.

Обязательный результат
В готовом прототипе должны работать четыре ключевых действия:

   создание задачи / напоминания;
   создание встречи;
   получение списка задач и встреч за указанный период;
   поиск ранее созданной задачи или встречи по запросу пользователя.

Ассистент должен сохранять созданные данные между запросами.

Что можно выбрать самостоятельно
Кандидат самостоятельно выбирает:
   язык программирования и стек;
   используемую LLM;
   способ распознавания и синтеза речи;
   базу данных;
   архитектуру приложения;
   способ поиска по старым задачам;
   формат пользовательского интерфейса.

Использование AI-инструментов при разработке разрешено.

Что предоставить по результатам
Необходимо предоставить:

 1. Ссылку на репозиторий с исходным кодом.
 2. README с инструкцией по запуску.
 3. Краткое описание архитектуры и выбранных технологий.
 4. Ссылку на работающий прототип.

В README также желательно коротко описать, какие решения были приняты
самостоятельно и что кандидат улучшил бы в продукте при наличии дополнительного
времени.

Дополнительные возможности
Не являются обязательными, но будут плюсом:

   изменение и удаление задач голосом;
   отметка задачи выполненной;
   обработка конфликтующих встреч;
   повторяющиеся задачи и встречи;
   контекст диалога («А перенеси ее на завтра»);
   семантический поиск по старым задачам;
   интеграция с реальным календарем;
   поддержка нескольких пользователей;
   обработка неоднозначных запросов и уточняющий диалог.

Критерии оценки
При оценке будут учитываться:

Работоспособность — насколько стабильно выполняются основные сценарии.
Качество понимания запросов — способен ли ассистент работать с естественными
формулировками, а не только с жестко заданными командами.

Архитектура — насколько понятно разделены работа с голосом, LLM, бизнес-логика и
хранение данных.

Работа с данными — корректность создания, получения и поиска задач и встреч.

Качество кода — структура проекта, читаемость и обоснованность технических решений.

UX — насколько естественно проходит взаимодействие с ассистентом, включая ситуации,
когда ему не хватает информации.
