# ADR-004: Хранение даты и времени записи: due_date (дата МСК) + starts_at (UTC мс)

## Context
Задача может быть без даты или с датой без времени (AC-02, AC-03), встреча и напоминание — с точным временем (AC-01, AC-04). Списки берутся по календарным дням Москвы (AC-06..AC-09, AC-22), конфликты — по интервалам (AC-14).

## Decision
В `records` две колонки: `due_date TEXT NULL` (`YYYY-MM-DD`, день по Москве) и `starts_at INTEGER NULL` (UTC мс, Drizzle `timestamp_ms`).
- Инвариант: `starts_at` задан ⇒ `due_date` = московская дата `starts_at` (CHECK `starts_at IS NULL OR due_date IS NOT NULL`, остальное — в сервисе).
- Встреча и напоминание: оба поля обязательны (сервис отказывает, движок спрашивает). Задача: оба необязательны.
- Период = полуинтервал дней `[fromDate, toDate)`; выборка `due_date >= from AND due_date < to` (сравнение ISO-строк). Сортировка: `due_date`, затем записи без времени, затем `starts_at`, затем `id`; без даты — в конце.
- Прошлое/будущее для поиска: момент записи = `starts_at`, иначе конец дня `due_date`; без даты — не участвует в фильтре времени.

## Alternatives
- Одна колонка `starts_at` с полуночью для «без времени» — не отличить «00:00» от «весь день».
- Хранить локальную строку `2026-10-20T10:00` — нарушает stack rule (instants в UTC), сравнения зависят от формата.

## Consequences
- Индекс `(user_id, due_date)` покрывает все списки.
- DTO отдаёт `date` и `time` (`HH:mm`, МСК) — форматирование одно в `src/shared/format.ts`.
