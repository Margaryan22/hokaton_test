# ADR-005: Поиск: фильтры типа и времени, затем балл по основам слов с синонимами; при равенстве — раньше по дате

## Context
AC-10..AC-12: поиск «по смыслу» без платных API по ≈1000 записям; не более 5 результатов; слово типа в запросе — фильтр («найди задачу про презентацию» не выдаёт напоминания и встречи); «была» — только прошлое (AC-11б: ровно id 309, 429, 530). ADR-001 выбрал стемминг Snowball + синонимы + нечёткость. Проверка: Snowball даёт «иван»→«ива», но «иваном»→«иван» — точное равенство основ не находит Ивана.

## Decision
Чистая функция `searchRecords(records, query, now)` в `src/server/search/rank.ts`; сервис передаёт ей все записи пользователя (уже отфильтрованные по `userId`).
1. Запрос (из NLU): `terms` (нормализованные слова без стоп-слов), `kind?`, `tense?` (`past` | `future`).
   Слова типа → `kind`: «задач*» → task; «встреч*» → meeting; «напомин*» → reminder (сами не термы). «созвон», «планерк», «демо» → kind meeting и остаются термами. Прошлое: «был/была/было/были», «ставил*», «прошл*»; будущее: «будет/будут», «запланирован*», «предстоящ*».
2. Фильтры до ранжирования: `kind`; `tense` относительно `now` (по ADR-004; записи без даты исключаются).
3. Балл термина по токенам записи (максимум из): равные основы — 1.0; префикс (токен одного начинается с основы другого, основа ≥ 3 букв) — 0.8; синоним из группы `synonyms.ts` — 0.6; Левенштейн по основам (≥5 букв, расстояние ≤1, ≥9 букв ≤2) — 0.4. Балл записи = сумма по терминам. Балл 0 — не выдаётся.
4. Порядок: балл ↓, дата ↑ (`starts_at`/`due_date`), id ↑. Лимит 5; ответ также сообщает общее число найденных.
5. Пустой запрос терминов (например, только «найди встречи») — список по фильтрам тем же порядком.
Тот же ранжировщик выбирает цель для удаления/отметки/переноса: кандидаты — записи с максимальным баллом (без фильтра времени); один — цель, несколько — выбор до 5 (AC-17), ноль — «Не нашёл …».

## Alternatives
- SQL `LIKE` — не складывает регистр кириллицы, не знает словоформ.
- Эмбеддинги (локальная модель) — десятки МБ, холодный старт serverless (ADR-001).
- TF-IDF/BM25 — для коротких строк из 3–5 слов не лучше суммы совпадений, сложнее объяснить проверяющему порядок.

## Consequences
- Детерминированно: тесты на реальном CSV проверяют AC-10, AC-11, AC-12 по id.
- «По смыслу» = словоформы + синонимы; расширение — правка `synonyms.ts` с тестом.
- Основы записей вычисляются на каждый запрос (≈1000×5 токенов — миллисекунды); кэш не нужен.
