# ADR-007: Необязательный LLM-разбор не делаем: только правила

## Context
ADR-001 и бриф (Integrations) допускали необязательный LLM-фолбэк для нераспознанных фраз при `LLM_API_KEY`. Ключа у владельца нет (интервью), AC-23 требует, чтобы всё работало без ключа, проверяющие тоже запустят без ключа.

## Decision
LLM-фолбэк не строим. `parse()` — только правила. Переменные `LLM_API_KEY`/`LLM_MODEL` убраны из `.env.example`; раздел «Optional LLM» в `.crew/stack/nlu-search.md` заменён запретом. Нераспознанное → ответ «не понял» с примерами (AC-13).

## Alternatives
- Фолбэк через `fetch` к провайдеру — никто из проверяющих его не увидит; не покрывается e2e (тесты запрещают ключ); добавляет недетерминизм, таймауты и поверхность для prompt injection; отнимает время у правил, по которым оценивается понимание.
- Бесплатный LLM-эндпоинт без ключа — ненадёжен и передаёт тексты третьей стороне.

## Consequences
- Качество понимания целиком в правилах и их тестах; время идёт на перефразировки фраз из ТЗ.
- Единая сигнатура `parse(text, expect, now): Intent` позволяет позже подключить LLM-парсер вторым звеном — упоминается в README «что улучшить».
- Частично заменяет пункт NLU в ADR-001.
