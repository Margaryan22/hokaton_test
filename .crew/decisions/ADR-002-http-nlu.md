# ADR-002: Слои и конвейер реплики: голос → HTTP → NLU → диалоговый движок → сервисы/поиск → хранение

## Context
Бриф (Constraints, AC-24) требует явного разделения: голос (браузер), понимание запроса, бизнес-логика, хранение; ТЗ оценивает архитектуру. ADR-001 задал стек, но не порядок вызовов между модулями: парсеру нужен контекст диалога (ждём ли мы ответ «да/нет», время, номер), а диалогу — результат парсера и данные.

## Decision
Один путь для каждой реплики (голосовой и текстовой одинаково):
1. **Голос** `src/client/speech/*` — Web Speech API превращает речь в текст и озвучивает ответ; сервер не знает, как введён текст.
2. **HTTP** `src/app/api/**` — Zod-проверка, пользователь из cookie, `now()` из `clock.ts`, вызов одной функции, JSON.
3. **Диалоговый движок** `src/server/dialog/engine.ts` — `handleUtterance(userId, text, now)`: загружает состояние диалога, зовёт парсер с ожидаемым видом ответа, выполняет переход конечного автомата, вызывает сервисы, формирует ответ через `replies.ts`, сохраняет реплики и новое состояние — одной транзакцией.
4. **NLU** `src/server/nlu/*` — чистая функция `parse(text, expect, now): Intent`, без БД и без состояния.
5. **Сервисы** `src/server/services/*` (записи, конфликты, пользователи) и **поиск** `src/server/search/*` (чистое ранжирование списка записей).
6. **Хранение** `src/db/*` — Drizzle-репозитории, каждый принимает `userId` первым аргументом.

Правило импорта: api → dialog → {nlu, services, search, replies}; services → {db, search}; nlu и search импортируют только `src/shared`, luxon и stemmer; db не импортирует `src/server`.

## Alternatives
- Парсер вызывает сервисы сам (NLU с доступом к БД) — смешивает понимание и данные, парсер не тестируется без БД.
- Состояние диалога на клиенте — клиент мог бы подменить запись для удаления (security rule 8); контекст терялся бы между вкладками.
- LLM-агент с инструментами вместо автомата — нужен ключ (запрещено AC-23), недетерминирован.

## Consequences
- NLU и поиск тестируются таблицами фраз без БД; движок — на in-memory БД.
- Добавление интента = правило в `nlu/intents.ts` + ветка в движке + шаблон ответа.
- Конвенция 1 в `.crew/stack/README.md` уточнена под этот порядок.
