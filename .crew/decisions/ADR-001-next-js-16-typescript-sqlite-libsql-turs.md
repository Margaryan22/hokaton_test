# ADR-001: Стек: Next.js 16 + TypeScript, SQLite/libSQL (Turso) через Drizzle, правила NLU без платных API, Vercel

## Context
Бриф (.crew/brief.md) требует: русский NLU без платного ключа (детерминированный разбор интентов и относительных дат в Europe/Moscow с подменяемым «сейчас» для тестов; LLM — только необязательное улучшение), поиск «по смыслу» по 1000 строкам CSV без платных API, постоянное хранилище, переживающее перезапуск и «засыпание» бесплатного хостинга (AC-21), голос через Web Speech API браузера, несколько пользователей по имени без паролей, деплой на бесплатный хостинг, запуск проверяющим одной-двумя командами. Технологии владелец не задавал (Q13).

## Decision
- **Next.js 16.4 (App Router) + TypeScript 5.9 + React 19.3**, один язык для клиента и сервера. Страница — клиентский компонент; сервер — Route Handlers в `src/app/api/**`; логика (NLU, даты, поиск, сервисы) — чистые TS-модули в `src/server/**`, независимые от Next. Tailwind CSS 4 для стилей. Cache Components и React Compiler выключены (не нужны, усложняют).
- **База: SQLite через libSQL (`@libsql/client` 0.18) + Drizzle ORM 0.45 / drizzle-kit 0.31.** Локально — файл `data/app.db` (ничего ставить не нужно); на хостинге тот же драйвер с `DATABASE_URL=libsql://…turso.io` и токеном — бесплатная управляемая БД Turso, данные переживают перезапуск (AC-21). Миграции — SQL в `drizzle/`, применяются `npm run db:migrate`; сид идемпотентный.
- **NLU — собственный rule-based парсер на TS**: нормализация (нижний регистр, ё→е, числительные словами), интенты по шаблонам, относительные даты/время на **Luxon 3.7** в зоне Europe/Moscow; «сейчас» передаётся параметром, на границе API берётся из `src/server/clock.ts` (`APP_NOW` фиксирует его для тестов). Необязательный LLM (`LLM_API_KEY`) — только через `fetch` как запасной разбор нераспознанных фраз, без SDK; без ключа всё работает (AC-23).
- **Поиск — лексико-морфологический, в памяти процесса**: стемминг Snowball (`snowball-stemmers` 0.6) + словарь синонимов предметной области + нечёткое совпадение (`fastest-levenshtein`) + фильтры по типу и прошлому/будущему; ранжирование по весу совпадений, при равенстве — раньше по дате.
- **Валидация** входа API — **Zod 4.6**. **Тесты**: Vitest 5 (юнит, логика NLU/дат/поиска), Playwright 1.64 (e2e в Chromium, своя БД `data/e2e.db`, `APP_NOW=2026-10-19T10:00:00+03:00`, порт 3100). Линт — ESLint 9 + eslint-config-next, типы — `tsc --noEmit`.
- **Пользователи без паролей**: выбранный пользователь хранится в cookie с его id; сервер берёт владельца только из неё и фильтрует все запросы по владельцу.
- **Хостинг: Vercel (Hobby) + Turso (Free)**, регион fra1/aws-eu-central-1; `vercel.json` запускает миграции и сид перед сборкой. Нужны аккаунты владельца (access-checklist).

## Alternatives
- **Vite + Express/Hono** — два процесса и больше ручной настройки; Next.js даёт одну команду, официальный генератор и бесплатный деплой.
- **PostgreSQL (Neon/Supabase) + PGlite локально** — два разных драйвера, сложнее для проверяющего; SQLite/libSQL — один драйвер и файл локально.
- **SQLite-файл на диске хостинга (Render/Koyeb free)** — эфемерный диск теряет данные при засыпании, нарушает AC-21. Персистентные тома на бесплатных тарифах практически недоступны.
- **chrono-node (ru)** для дат — частичная поддержка русского и непрозрачные ошибки; собственные правила проще проверить тестами на фразах из AC.
- **Локальная эмбеддинг-модель (@huggingface/transformers, multilingual-e5-small)** — десятки МБ весов и холодный старт в serverless; для 1000 коротких строк стемминг + синонимы + нечёткость достаточны. Оставлено в «что улучшить».
- **Платный LLM как основной NLU** — запрещено брифом (нет ключа).

## Consequences
- Проверяющий запускает `npm run setup` и `npm run dev` (Node ≥ 22.12, больше ничего).
- Качество понимания определяется правилами: фразы из AC и их вариации покрываются юнит-тестами; нераспознанное — уточняющий вопрос (AC-13).
- Поиск без эмбеддингов: «по смыслу» достигается синонимами; новые синонимы добавляются в словарь.
- Для публичной ссылки владелец создаёт аккаунты Vercel и Turso и задаёт `DATABASE_URL`/`DATABASE_AUTH_TOKEN`; до этого всё проверяется локально.
- `npm audit` сообщает уязвимости только в dev-зависимостях (eslint-config-next, drizzle-kit); в продакшен-зависимостях их нет.
