# Next.js 16 (App Router)

## Version and sources
- next 16.4.2, React 19.3, Turbopack (default for dev and build).
- https://nextjs.org/docs/app/guides/upgrading/version-16 (breaking changes, removals)
- https://nextjs.org/docs/app/api-reference/file-conventions/route (route handlers, cookies, params)
- Version-matched docs are also bundled in `node_modules/next/dist/docs/`.

## How we use it here
- One page: `src/app/page.tsx` renders the client app (`src/components/AssistantApp.tsx`, `"use client"`). No other pages are needed.
- All data goes through JSON route handlers under `src/app/api/**/route.ts`. No Server Actions, no data fetching in Server Components — one clear HTTP boundary that QA can call directly.
- Route handlers are thin: parse input (Zod), resolve the current user from the cookie, call a function in `src/server/services/**`, return `Response.json(...)`.
- `cacheComponents` and the React Compiler are **off** (`next.config.ts`). Do not turn them on.
- `next.config.ts` reads `NEXT_DIST_DIR` so e2e tests (`.next-e2e`) can run beside a developer's `next dev` (Next.js locks the dist dir).
- `@libsql/client` and `libsql` are in Next's built-in `serverExternalPackages`; nothing to configure.

## Do
- Make request APIs async: `const store = await cookies()`; `const { id } = await ctx.params`.
  ```ts
  import { cookies } from "next/headers";
  import type { NextRequest } from "next/server";

  export async function PATCH(request: NextRequest, ctx: RouteContext<"/api/records/[id]">) {
    const { id } = await ctx.params;
    const userId = await requireUserId(); // reads (await cookies()).get("uid")
    const body = UpdateRecordSchema.safeParse(await request.json().catch(() => null));
    if (!body.success) return Response.json({ error: { code: "invalid_input", message: "Некорректные данные" } }, { status: 400 });
    return Response.json(await updateRecord(userId, Number(id), body.data));
  }
  ```
- `RouteContext<'/path/[id]'>`, `PageProps`, `LayoutProps` are global types generated by `next typegen` (run by `npm run typecheck`, `dev`, `build`).
- Add `export const dynamic = "force-dynamic";` to GET handlers that do not read the request (otherwise they may be prerendered at build time).
- Set cookies in route handlers with `(await cookies()).set(name, value, { httpOnly: true, sameSite: "lax", path: "/", maxAge })`.
- Read env vars on the server only (`process.env.X`); anything the browser needs must be returned by an API or be `NEXT_PUBLIC_*` (none needed now).
- Catch expected errors in the handler and map them to `{ error: { code, message } }`; let unexpected ones throw (Next returns 500 and logs).

## Don't
- No `middleware.ts` — it is deprecated in 16 (renamed `proxy.ts`); we do not need either.
- No synchronous `cookies()`, `headers()`, `params` — removed in 16.
- No `next lint` (removed) — use `npm run lint`. No `serverRuntimeConfig`/`publicRuntimeConfig` (removed).
- No `revalidateTag`, `"use cache"`, ISR — the app is fully dynamic per user.
- Do not import `src/db/**` or `src/server/**` from a `"use client"` file — they would leak into the browser bundle and fail on `node:` modules.
- No `next/font/google` — it downloads fonts at build time; we use the system font stack in `globals.css`.
- Do not use the Edge runtime; route handlers run on Node.js (the libSQL driver needs it).

## Testing
- Route handlers are exercised end-to-end through Playwright (`request.post("/api/chat", …)` or the UI). Put logic in `src/server/**` so Vitest tests it without Next.
- `npm run typecheck` must pass — it regenerates route types first.

## Security
- The user id comes only from the httpOnly cookie set by `/api/session`; validate it exists in `users` on every request.
- Validate every body and query param with Zod; reject unknown shapes with 400.
- Never echo stack traces or SQL errors to the client.
