# T-009: Fix e2e dev server: HMR reload loop with NEXT_DIST_DIR

## Goal
With `NEXT_DIST_DIR=.next-e2e` in playwright.config.ts the e2e dev server sends `reloadPage "HMR hash mismatch"` on every page load, so the page reloads endlessly and UI tests fail (message field stays disabled). Fix the e2e web server setup so browser tests load the page normally (e.g. run the e2e server as a production build `next build && next start` with its own distDir, or another approach that keeps e2e runnable while `npm run dev` is up on :3000), keep APP_NOW and the separate e2e DB, and set `RATE_LIMIT_DISABLED=1` in the e2e server env (implemented by T-008). Strengthen the smoke test so it fails when the page is stuck (e.g. the message field becomes enabled after selecting a user).

## Acceptance
- `npm run test:e2e`: the UI tests in e2e/ui.spec.ts load the page without reload loops; report the full suite result.
