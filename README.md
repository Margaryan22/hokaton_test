# Голосовой ассистент: задачи, напоминания, встречи

Прототип веб-ассистента: голосом или текстом на русском, свободными фразами, создаёт задачи, напоминания и встречи, показывает планы на период и находит старые записи. Отвечает текстом и голосом. Платные ключи и внешние API не нужны.

- Репозиторий: _ссылка добавляется после публикации_
- Работающий прототип: _ссылка добавляется после деплоя_ (открывается без пароля: имя пользователя выбирается или создаётся в переключателе)

## Быстрый старт (локальный запуск)

Нужен только Node.js 22.12+ (проверено на Node 24). Ставить базу данных, Docker и что-либо ещё не нужно.

```bash
npm run setup   # зависимости, локальная БД data/app.db, миграции, 1000 записей пользователя «Демо» из CSV
npm run dev     # http://localhost:3000
```

Голосовой ввод работает в Chrome и Edge (Web Speech API), текстовый — в любом браузере.

Что попробовать:

- «Напомни мне завтра в 10 утра позвонить Ивану», «В пятницу нужно отправить отчёт», «Поставь встречу с Иваном завтра» → «На какое время?» → «в 14:30»
- «Что у меня на этой неделе?», «Есть ли у меня встречи сегодня?»
- «А перенеси её на завтра», «Отметь задачу купить билеты выполненной», «Удали задачу купить билеты»
- пользователь «Демо»: «Найди задачу про презентацию», «Когда у меня была встреча с Иваном?», «Что было 26 января 2024?»

## Настройки (`.env`)

Скопируйте `.env.example` в `.env` (setup работает и без этого — по умолчанию `file:./data/app.db`). Обязательных ключей нет.

| Переменная | Назначение |
|---|---|
| `DATABASE_URL` | `file:./data/app.db` локально; `libsql://….turso.io` на хостинге |
| `DATABASE_AUTH_TOKEN` | токен Turso (только для хостинга) |
| `APP_NOW` | зафиксировать «сейчас», например `2026-10-19T10:00:00+03:00`; пусто — реальное время МСК. Только для тестов |
| `RATE_LIMIT_DISABLED` | `1` отключает ограничение частоты запросов. **Только для e2e-тестов** (его ставит `playwright.config.ts`); в продакшене никогда не задавайте |

## Деплой (бесплатно: Vercel + Turso)

1. В веб-консоли [Turso](https://app.turso.tech) (тариф Free) создайте базу `voice-assistant` в регионе Frankfurt (AWS eu-central-1), скопируйте её URL (`libsql://…`) и создайте токен доступа (Create Token).
2. Опубликуйте репозиторий на GitHub и импортируйте его в [Vercel](https://vercel.com) (Hobby). Фреймворк определится сам; команда сборки берётся из `vercel.json`: миграции и идемпотентный сид выполняются перед `next build`, регион функций — `fra1`.
3. В Vercel → Settings → Environment Variables (Production и Preview) задайте `DATABASE_URL` и `DATABASE_AUTH_TOKEN` из шага 1. **Не задавайте `APP_NOW` и `RATE_LIMIT_DISABLED`**: первое заморозит время, второе снимет защиту от перебора и спама.
4. Deploy. Откройте выданный адрес, выберите пользователя «Демо» и проверьте «Что было 26 января 2024?». Данные хранятся в Turso и переживают перезапуски и «засыпание».
5. Впишите ссылки на репозиторий и прототип в начало этого README.

## Архитектура и технологии

Подробно — [`docs/architecture.md`](docs/architecture.md) (слои, модель данных, API, NLU, диалоговый автомат, поиск, соответствие критериям); решения с альтернативами — `.crew/decisions/ADR-*.md`.

Каждая реплика (голосом или текстом) идёт одним путём, слои разделены по ТЗ:

| Слой | Где | Что делает |
|---|---|---|
| Голос | `src/client/speech` | Web Speech API браузера: речь → текст, озвучивание ответа |
| HTTP | `src/app/api` | проверка входа (Zod), пользователь из cookie, вызов движка, JSON |
| Понимание запроса | `src/server/nlu`, `src/server/search` | чистые функции: интент, тип, даты и время по Москве, текст записи; ранжирование поиска |
| Бизнес-логика | `src/server/dialog`, `src/server/services` | автомат диалога (уточнения, подтверждения, выбор, контекст «её»), записи, конфликты встреч |
| Хранение | `src/db` | Drizzle + libSQL: файл SQLite локально, Turso на хостинге; каждый запрос фильтруется по пользователю |

Выбранные технологии (ADR-001):

- **Next.js 16 + TypeScript (strict), React 19, Tailwind CSS 4** — один язык и один процесс для клиента и сервера, бесплатный деплой на Vercel.
- **SQLite через libSQL + Drizzle ORM** — локально файл без установки, на хостинге тот же драйвер к бесплатной управляемой Turso; данные не теряются при «засыпании».
- **Luxon** — даты и время в Europe/Moscow; «сейчас» передаётся параметром, поэтому логика детерминирована и тестируема.
- **Snowball-стеммер + словарь синонимов + fastest-levenshtein** — поиск по словоформам и с опечатками без внешних моделей.
- **Web Speech API** — распознавание и синтез речи без ключей.
- **Zod** — проверка входа API; **Vitest** — юнит-тесты логики; **Playwright** — e2e по критериям приёмки.

## Решения, принятые самостоятельно

ТЗ не задаёт эти детали; ниже — что выбрано и почему.

- **Правила вместо LLM** (ADR-007). Понимание запроса — собственный разбор на правилах: нормализация, числительные словами, относительные даты и время. Ключ не нужен, ответы детерминированы и покрыты тестами на фразах из критериев; нет риска prompt injection и утечки текстов третьей стороне.
- **Пользователи без паролей.** Открытая ссылка, имя выбирается или создаётся одним действием, выбранный пользователь хранится в cookie; сервер берёт владельца только из неё. Записи и поиск изолированы по пользователю. Это не защита от того, кто знает чужое имя, поэтому личные данные в прототип не вводите.
- **Состояние диалога на сервере** (ADR-003): конечный автомат в таблице `dialog_states` и «фокусная» запись для «её/эту». Подтверждение удаления применяется только к записи, сохранённой на сервере. Контекст переживает перезагрузку и работает на serverless.
- **Уточняющие вопросы**: встреча и напоминание без времени или даты → вопрос; задача без времени допустима. Удаление — только после «да». Пересечение встреч (длительность 1 час) → «Всё равно поставить?». Несколько подходящих записей → нумерованный выбор до 5.
- **Трактовки времени**: «до конца недели» — воскресенье; «в пятницу» — ближайшая будущая; «утром» — 09:00, «вечером» — 19:00; голый час 1–7 — дневной («в 3» → 15:00). Всё в Europe/Moscow.
- **Хранение даты** (ADR-004): день по Москве и момент в UTC — отдельные поля, чтобы отличать «весь день» от «00:00».
- **Поиск** (ADR-005): фильтр по типу и прошлому/будущему («была» / «будет»), затем балл по основам слов, синонимам и опечаткам; при равенстве — раньше по дате; не больше 5 результатов.
- **CSV из ТЗ** (ADR-006) принадлежит пользователю «Демо»; тип записи — по началу текста («встреча», «созвон», «демо», «планерка» → встреча; «напомнить» → напоминание; иначе задача). Импорт идемпотентный (уникальный `user_id + source_id`), повторный деплой не создаёт дублей.
- **Безопасность прототипа**: ограничение частоты запросов к чату и смене пользователя, заголовки безопасности (`nosniff`, `DENY` для фреймов, микрофон только для своего сайта), реплика не длиннее 500 символов, ESLint запрещает клиентскому коду импортировать серверные модули и драйвер БД. Заголовок удалённой записи остаётся в старых сообщениях диалога до «Нового диалога».

## Что улучшить при наличии времени

- **Напоминания в назначенное время**: push-уведомления (Web Push) или сообщения в мессенджер — сейчас напоминание только хранится и показывается в списке.
- **Повторяющиеся задачи и встречи** («каждый понедельник в 10») и **интеграция с календарём** (Google Calendar, CalDAV, экспорт .ics).
- **Семантический поиск**: эмбеддинги (например, multilingual-e5) в Turso vector — для запросов без общих слов с текстом записи.
- **Гибридное понимание**: необязательный LLM-разбор для фраз, которые правила не поняли, с проверкой результата той же схемой и тем же диалоговым автоматом.
- **Вход по ссылке или паролю** вместо открытого выбора имени; часовой пояс пользователя вместо фиксированной Москвы.
- **Голос**: серверное распознавание (Vosk / Whisper) для Firefox и Safari, где нет Web Speech API; потоковый ввод без кнопки.
- **Длительность встреч и время окончания** из фразы («с 15 до 17»), перенос на «через неделю», массовые операции («удали все задачи на завтра»).
- **Эксплуатация**: общий rate limit через Turso/KV вместо памяти процесса, CSP с nonce, мониторинг ошибок.
